# مِرسى — منصة طلب القهوة من السيارة

تطبيق ويب عربي متكامل ومتعدد الفروع لاستقبال طلبات المقهى من السيارة، تشغيلها
لحظيًا، وإدارة الولاء والمدفوعات والمحتوى. لا يحتوي المشروع على Mock API أو
بيانات تجريبية أو مسار نجاح وهمي؛ عند غياب خدمة خارجية تظهر حالتها بوضوح على
أنها غير مفعّلة.

## ما الذي يتضمنه المشروع؟

- تجربة عميل RTL: الفروع، المنيو، الخيارات، السلة، الدفع، التتبع اللحظي،
  السيارات، الطلبات، الإشعارات، الكوبونات، الولاء وQR.
- بطاقة ولاء قابلة للتخصيص عبر Fabric.js مع وجهين، ملصقات، نصوص، تراجع/إعادة،
  فحص مناطق QR والهوية، وحفظ إصدارات التصميم.
- شاشات تشغيل لحظية للكاشير والباريستا والتسليم، مع انتقالات حالة محكومة من
  الخادم.
- لوحة إدارة للفروع والمنتجات والتوفر والمواقف والموظفين والصلاحيات والحملات
  والمدفوعات والتقارير والتدقيق والإعدادات.
- PWA متجاوبة، وضع داكن، حالات تحميل/فراغ/خطأ، وتهيئة أولى دون Seed تجريبي.
- Supabase Auth وPostgreSQL وStorage وRealtime وEdge Functions مع RLS على جميع
  الجداول، وعمليات مالية وولاء ذرية وقابلة لإعادة المحاولة بأمان.

## المعمارية

يستخدم المتصفح React وTypeScript وTanStack Query وReact Hook Form وZod.
Supabase هو مصدر الحقيقة الوحيد للبيانات. لا يقرر المتصفح سعرًا أو خصمًا أو
استحقاق ولاء أو حالة دفع؛ تعاد قراءة هذه القيم والتحقق منها في PostgreSQL وEdge
Functions. التفاصيل في:

- `docs/ARCHITECTURE_AR.md`
- `docs/SECURITY_MODEL_AR.md`

## المتطلبات

- Node.js 22.13 أو أحدث.
- مشروع Supabase مع صلاحية تشغيل migrations وEdge Functions.
- حساب مزود دفع. التكامل الجاهز افتراضيًا هو Moyasar، ويمكن تهيئة موصل متوافق
  لبقية المزودين.
- اختياريًا: WhatsApp Business Cloud API، خدمة إزالة خلفية، خدمة فحص صور،
  وخدمة HTML-to-PDF.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env.local`.
2. ضع `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`.
3. ثبّت الحزم وشغّل التطبيق:

```bash
npm install
npm run dev
```

يفتح التطبيق على `http://localhost:3000`. إذا لم تضبط Supabase ستظهر شاشة ربط
صريحة بدل بيانات وهمية.

## إعداد Supabase

اربط المجلد بمشروعك ثم طبّق migrations بالترتيب:

```bash
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase db push
```

الملفات الأربعة في `supabase/migrations/` تنشئ المخطط، الدوال الذرية، RLS،
سياسات Storage، Realtime، ومعاملة التأسيس الأولى. بعد ذلك اضبط أسرار الوظائف:

```bash
supabase secrets set \
  INITIAL_SETUP_TOKEN="a-long-one-time-secret" \
  QR_TOKEN_SECRET="a-separate-long-secret" \
  PAYMENT_PROVIDER="moyasar" \
  PAYMENT_SECRET_KEY="..." \
  PAYMENT_WEBHOOK_SECRET="..."
```

أضف أسرار WhatsApp ومعالجة الصور وPDF من `.env.example` فقط إذا فعّلت تلك
الخدمات، ثم انشر الوظائف:

```bash
supabase functions deploy
```

ضبط `supabase/config.toml` التحقق من JWT بحيث تكون وظائف Webhook والتأسيس فقط
قابلة للاستدعاء دون جلسة مستخدم؛ وتتحقق هذه الوظائف من أسرارها داخل الخادم.

## التأسيس الأول

1. افتح التطبيق بعد ربط Supabase.
2. أدخل رمز `INITIAL_SETUP_TOKEN`.
3. أنشئ أول مدير عام وفرع، واضبط الضريبة والولاء والدفع وواتساب والموقف وأول
   تصنيف ومنتج.
4. سجّل دخول المدير بالبريد وكلمة المرور اللذين أدخلتهما.

تُنفذ هذه الخطوة مرة واحدة داخل معاملة ذرية. لا توجد بيانات تجريبية، ولا يمكن
إعادة التأسيس بعد اكتماله.

## الدفع والـ Webhooks

- رمز البطاقة ينشأ في متصفح العميل مباشرة لدى بوابة الدفع؛ لا يمر رقم البطاقة
  أو CVV عبر خادم التطبيق.
- `payment-create` ينشئ محاولة دفع حقيقية ويربطها بالطلب.
- لا تصبح الدفعة ناجحة من صفحة الرجوع. `payment-webhook` وحدها تتحقق من السر
  والمبلغ والعملة ومعرف المزود، وتسجل الحدث بشكل idempotent قبل اعتماد الطلب.
- عرّف رابط Webhook لدى المزود بالشكل:
  `https://YOUR_PROJECT.supabase.co/functions/v1/payment-webhook`.
- الاسترجاع يمر عبر `refund-payment` ثم يُسجل في `refunds` ويرتبط بعكس الولاء
  عند الاسترجاع الكامل.

## واتساب والخصوصية

عرّف رابط Webhook في Meta على:
`https://YOUR_PROJECT.supabase.co/functions/v1/whatsapp-webhook`.
الحملات التسويقية تستبعد تلقائيًا كل من لم يمنح موافقة WhatsApp فعالة.
`whatsapp-send` لا يسجل الرسالة كمرسلة إلا إذا أعاد المزود معرف رسالة حقيقيًا.
صور العميل خاصة وتُعرض بروابط موقعة قصيرة العمر، ويجب رفع أصول الملصقات مع
تأكيد ملكية الحقوق.

## التحقق والجودة

```bash
npm run typecheck
npm test
npm run build
```

الاختبارات تتحقق من قاعدة الولاء (6 ثم السابعة)، الحد الأدنى، التحولات المسموحة
للطلب، وعقود migrations/RLS، بالإضافة إلى نجاح بناء التطبيق.

## متغيرات البيئة

القائمة الكاملة موثقة في `.env.example`. الأسرار التي تحمل أسماء
`SERVICE_ROLE` و`SECRET` و`TOKEN` لا توضع أبدًا في متغيرات `NEXT_PUBLIC_*` ولا
تُضمّن في المستودع. متغيرات `NEXT_PUBLIC_*` الوحيدة هي إعداد الاتصال العام
بـSupabase والمفتاح العام لبوابة الدفع وعنوان التطبيق.

## بنية المشروع

```text
app/                    طبقة التطبيق والتوجيه والثيم
components/             عناصر الواجهة وإطار التطبيق
features/               صفحات العميل والتشغيل والإدارة والمحرر
lib/                    الاتصال وموفرو الحالة وقواعد المجال
public/                 PWA والأيقونات وصورة المشاركة
supabase/migrations/     المخطط والأمان والدوال الذرية
supabase/functions/      التكاملات الخلفية وWebhooks
tests/                   اختبارات قواعد المجال وعقود الأمان والبناء
docs/                    توثيق المعمارية ونموذج التهديدات
```

## النشر

ابنِ نسخة الإنتاج باستخدام `npm run build`، وانشر الواجهة على مضيف يدعم تطبيق
Next/vinext، واضبط متغيرات الواجهة في بيئة النشر. Supabase وEdge Functions
تنشران بشكل مستقل وفق الخطوات أعلاه. تحقق بعد النشر من OTP، إنشاء الطلب،
Webhook الدفع، تحديث Realtime، QR، واتساب والاسترجاع باستخدام حسابات Sandbox
الخاصة بالمزود قبل تفعيل مفاتيح الإنتاج.
