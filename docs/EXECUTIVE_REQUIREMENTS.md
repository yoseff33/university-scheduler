# أولاً: القيود التقنية الإلزامية

يجب الالتزام بالتقنيات التالية فقط:

## الواجهة الأمامية

* React.
* TypeScript.
* Vite.
* Tailwind CSS.
* HashRouter من React Router لضمان عمل التوجيه على GitHub Pages.

## الخدمات الخلفية وقاعدة البيانات

* Supabase Auth.
* Supabase PostgreSQL.
* Supabase Storage.
* Supabase Realtime.
* Supabase Edge Functions.
* Supabase Row Level Security.

## الاستضافة

* استضافة الواجهة على GitHub Pages فقط.
* استخدام Supabase للخدمات الخلفية وقاعدة البيانات والتخزين والمصادقة والدوال الخلفية.

لا تستخدم:

* خادماً خارجياً مستقلاً.
* Firebase.
* Node.js Server منفصلاً.
* MongoDB.
* Mock APIs.
* JSON Server.
* بيانات تجريبية داخل التطبيق النهائي.
* LocalStorage كمصدر رئيسي للبيانات.
* أي محاكاة وهمية للخدمات الخارجية.

يمكن استخدام LocalStorage فقط لأمور مؤقتة وغير حساسة، مثل:

* تفضيل اللغة.
* حالة فتح القائمة.
* مسودة سلة غير مؤكدة.

لكن يجب أن تكون Supabase هي المصدر الأساسي والوحيد للحقيقة بالنسبة إلى:

* المستخدمين.
* الطلبات.
* المنتجات.
* الأسعار.
* المدفوعات.
* الولاء.

* الصلاحيات.
* الفروع.

# المرحلة الأولى: إعداد المشروع والمصادقة

## 1. إنشاء المشروع

أنشئ مشروعاً باستخدام:

* Vite.
* React.
* TypeScript.
* Tailwind CSS.

استخدم `HashRouter` حتى تعمل جميع المسارات على GitHub Pages دون أخطاء 404.

## 2. دعم PWA

أضف:

* `manifest.json`.
* أيقونات التطبيق.
* Service Worker.
* اسم التطبيق: فايبز.
* الاسم المختصر: Vibes.
* إمكانية تثبيت الموقع على الشاشة الرئيسية.

يجب ألا يقوم Service Worker بتخزين بيانات حساسة أو إرجاع بيانات قديمة للطلبات والمدفوعات.

## 3. المصادقة

استخدم Supabase Auth برقم الجوال وOTP حقيقي.

إذا لم يتم إعداد مزود SMS فعلي في Supabase:

* لا تعرض رمزاً تجريبياً.
* لا تنشئ تسجيل دخول وهمياً.
* اعرض رسالة:

> تسجيل الدخول برقم الجوال غير مفعّل حالياً.

## 4. جدول الملفات الشخصية

أنشئ جدول:

```sql
profiles
```

ويحتوي على الأقل على:

```text
id
phone
membership_number
name
avatar_url
preferred_branch_id
created_at
updated_at
```

الشروط:

* `id` مرتبط بـ `auth.users.id`.
* `membership_number` نص فريد.
* رقم العضوية يتكون من 7 أرقام فعلية.
* يمكن عرضه في الواجهة بصيغة `VIB-1234567`.
* الرقم المخزن لا يتكرر.
* إنشاء فهرس Unique على رقم العضوية.

## 5. إنشاء الملف الشخصي

أنشئ آلية آمنة لإنشاء Profile بعد إنشاء مستخدم جديد، بإحدى الطريقتين:

* Database Trigger آمن.
* Edge Function باسم `create-profile`.

يجب أن:

* تتحقق من هوية المستخدم.
* تنشئ رقم عضوية فريداً.
* تمنع إنشاء أكثر من Profile للمستخدم نفسه.
* تسجل العملية في Audit Log عند الحاجة.

## 6. سياسات RLS

فعّل RLS على جدول `profiles`.

السياسات المطلوبة:

* العميل يرى ملفه فقط.
* العميل يعدل الحقول المسموح بها في ملفه فقط.
* العميل لا يستطيع تعديل رقم العضوية.
* المدير المخول يستطيع الاطلاع وفق صلاحياته.
* لا يستطيع أي مستخدم تعديل دوره أو صلاحياته بنفسه.

## 7. صفحة حسابي

بعد تسجيل الدخول، تعرض صفحة حساب العميل:

* الاسم.
* الصورة.
* رقم الجوال.
* رقم العضوية.
* QR Code مبني على رقم العضوية أو رابط تحقق آمن.
* عدد أكواب الولاء الحقيقي.
* حالة المكافأة.
* السيارات المحفوظة.
* الطلبات السابقة.
* التصميم النشط لبطاقة الولاء.

# المرحلة الرابعة: الدفع الإلكتروني

أنشئ Edge Function باسم:

```text
create-payment
```

مهمتها:

* التحقق من هوية المستخدم.
* التحقق من ملكية الطلب.
* التحقق من أن الطلب غير مدفوع.
* جلب المبلغ الحقيقي من قاعدة البيانات.
* إنشاء جلسة دفع مع بوابة دفع سعودية مدعومة.
* حفظ مرجع العملية.
* إعادة رابط الدفع الحقيقي فقط.

أنشئ Edge Function أو Webhook باسم:

```text
confirm-payment
```

مهمتها:

* التحقق من توقيع Webhook.
* منع تكرار معالجة العملية.
* مطابقة المبلغ والعملة والطلب.
* تحديث حالة الدفع.
* تحديث حالة الطلب.
* تسجيل العملية في `payment_logs`.
* استدعاء منطق منح كوب الولاء إذا كان الطلب مؤهلاً.

يُمنع:

* اعتبار عملية الدفع ناجحة اعتماداً على Redirect فقط.
* منح كوب بمجرد عودة العميل إلى الموقع.
* قبول مبلغ مرسل من الواجهة.
* تخزين مفتاح بوابة الدفع داخل Vite.

إذا لم يتم إعداد بوابة دفع:

* عطّل الدفع الإلكتروني.
* اسمح بالدفع عند الاستلام فقط إذا كان الفرع يفعّله.
* اعرض رسالة:

> الدفع الإلكتروني غير مفعّل حالياً.

# المرحلة الخامسة: برنامج ولاء فايبز

## قاعدة البرنامج

يحصل العميل على كوب ولاء واحد عند:

* اكتمال طلب مؤهل.
* أو تأكيد دفع طلب مؤهل.
* وصول قيمة الطلب المؤهلة إلى 12 ريالاً أو أكثر.
* عدم منح كوب سابق للطلب نفسه.

بعد جمع 6 أكواب نشطة، يحصل العميل على مكافأة مشروب مجاني وفق شروط الإدارة.

المنطق المعتمد:

* العداد يظهر من `0/6` إلى `6/6`.
* بعد اكتمال 6 أكواب تظهر رسالة:

> مبروك! مشروبك القادم علينا من فايبز.

يجب أن يكون عدد الأكواب المطلوبة قابلاً للتعديل من إعدادات النظام، وألا يكون ثابتاً داخل الواجهة.

```text

```

5. تضيف الكوب في معاملة واحدة.
6. تسجل العملية في سجل الولاء.
7. تكون Idempotent وتتحمل استدعاءها أكثر من مرة دون تكرار الكوب.

يتم استدعاؤها من:

* Webhook الدفع الإلكتروني.
